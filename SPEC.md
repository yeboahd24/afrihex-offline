# AfriHex code format

Version 1. Any implementation that follows this produces the same codes as the
AfriHex API. `test/vectors.json` holds reference codes generated by the API.

## Shape

```
AF-{COUNTRY}-{LEVEL}-{ID}
AF-GH-12-0GXTJJBE4RZZZ
```

| Part | Meaning |
|---|---|
| `AF` | Always `AF`. |
| `COUNTRY` | ISO 3166-1 alpha-2 country code. Only `GH` (Ghana) today. |
| `LEVEL` | H3 resolution, 0 to 15. 7 is about 2 km across, 12 about 20 m, 13 about 7 m. |
| `ID` | The H3 cell index (a 64-bit number) in Crockford base-32, most significant digit first, padded to 13 characters. |

Crockford base-32 alphabet: `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (no I, L, O or U).

## Encoding

1. Check the point is inside the country's border. Ghana's border is the
   polygon in `src/ghana.ts`. Outside it, there is no code.
2. Find the H3 cell containing the point at the chosen level (`latLngToCell`).
3. Write the cell index in base-32, 13 characters, and join the parts with `-`.

## Short form

H3 fills the digits below a cell's level with ones, so the ID ends in `Z`s
that carry no information (five at level 7). The short form drops all
trailing `Z`s: `AF-GH-7-0GXTJJBDZZZZZ` becomes `AF-GH-7-0GXTJJBD`.

To read a short code, pad the ID back to 13 characters with `Z`. Both forms
are the same cell. Store the full form; show people the short form.

## Decoding

1. Split on `-` into four parts; upper-case them.
2. Pad the ID to 13 characters with `Z`, read it as base-32.
3. The result must be a valid H3 cell, and its resolution must equal `LEVEL`.
   Otherwise the code is invalid (often a typo).

## Stability

Codes made under version 1 decode the same way forever. A change that would
alter existing codes would be a new version with a different shape.
